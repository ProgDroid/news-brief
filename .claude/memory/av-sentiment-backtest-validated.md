**Two validated, self-service ($49.99/mo, free 25/day), Feature-B paths — NEITHER needs the bigdata REST key (supersedes the Task-8 probe conclusion that a faithful backtest required RavenPack REST):**

1. **News-tone factor** (apples-to-apples with the inconclusive n≈18 MCP-approx pilot). `NEWS_SENTIMENT` returns numeric, entity-resolved per-ticker `ticker_sentiment_score` + `relevance_score` + `overall_sentiment_score`. Floor 2010, BUT density is the binding constraint: MU = **26 articles in 2016 vs 213 in 2024** → pre-~2018 too sparse for stable monthly aggregates on one name; effective good-density window ~2018–2026. AV samples "premier outlets," thinner than RavenPack's firehose.
2. **Transcript sentiment factor** (cleaner, complete). `EARNINGS_CALL_TRANSCRIPT` (params `symbol`, `quarter`=YYYYQM) returns per-segment `{speaker,title,content,sentiment}`; sentiment is real (MU 2024Q1: CEO turn 0.8, CFO 0.3, boilerplate 0.0; 15/36 nonzero, range 0→0.8). Coverage 2010→2024 essentially complete; isolated single-quarter holes (2011Q1 empty but 2010Q1/2011Q3/2012Q1/2015Q1 all present). Quarterly cadence = fewer obs/name, but spans more regimes.

**Point-in-time integrity (the backtest-killer I checked): OK.** AV scores old articles with its current model, but each score uses only that article's published-at-T text → no future leak in the feature; one fixed model across all eras = no model-drift bias. Not RavenPack's contemporaneous scoring, but legitimately backtest-grade. Real caveat is selection+variance in sparse early years, not lookahead.
